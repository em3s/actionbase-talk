# Narrative

## 한 줄

> **"3년 동안 만들어온 게 아니라, 3년 동안 자라왔다"**
>
> — 운영이 시스템을 자라게 한 흔적을 따라가는 회고.

## 7막 흐름

```
① 정체성       — 액션베이스가 뭐고 왜 만들었나
② 원장으로     — Wish 사례 (SSOT, 5단계 마이그레이션)
③ 뷰로         — Friends 사례 (CQRS, CDC로 옆에 붙이기)
④ 가능해진 것  — Now · Now+ · 멀티홉 (티저)
⑤ 검증 4 레이어 — 살아남는 방식 (티저)
⑥ 핸드오프     — 2세션 · 3세션으로
⑦ 닫기         — 자라온 길
```

## 막별 핵심

### ① 정체성

**무엇**: 좋아요·찜·최근 본 상품·친구 관계 — 사용자 상호작용 데이터베이스.

**왜**: 서비스마다 비슷한 데이터 구조와 처리를 반복해서 설계하고 있었다. 같은 문제를 같은 방식으로 다뤄볼 수 없을까.

**핵심 모델**: 엣지 하나 — `누가, 무엇을, 어디에 했다`.

**경계 (Focuses / Avoids)**: OLTP만. 분석·범용 그래프 쿼리는 의도적으로 안 한다.

### ② 원장으로 (Wish)

**상황**: 기존 MySQL + Batch + Redis. 트래픽 증가로 한계. 액션베이스가 첫 본진을 받음.

**해법**: 5단계 마이그레이션. 한 번에 갈아끼우는 게 아니라 신뢰가 쌓일 때마다 한 칸씩.

```
Stage 1: Dual Write       쓰기를 양쪽으로
Stage 2: Validation       1개월 비교 (MySQL dump ↔ AB CDC snapshot)
Stage 3: Dual Read        shadow read
Stage 4: Read Cutover     읽기 전환, 기존 시스템은 백업으로 유지
Stage 5: Cleanup          수개월 후 기존 시스템 제거
```

**원칙**: 각 단계마다 롤백할 길을 남긴다. 죽지 않을 길을 둘 이상.

### ③ 뷰로 (Friends)

**상황**: 카카오톡 친구 관계는 이미 잘 돌아가고 있음. MySQL 샤드 + HBase view. 다만 view가 특정 access pattern에만 맞춰져 새 쿼리 타입 추가가 어려움.

**해법**: 갈아끼우는 게 아니라 옆에 붙이기. Debezium CDC → Kafka → 액션베이스. 소스 DB는 한 줄도 안 바꿈.

**핵심**: 원장 vs 뷰는 우열이 아니라 상황에 맞는 선택.

### ④ 가능해진 것 (사다리)

원장이든 뷰이든, 일단 들어오면 같은 기능들이 따라온다.

```
Lv.1  GET / COUNT / SCAN       "내가 찜한 것"
Lv.2  Actionbase Now           "이 상품, 지금 32명"
Lv.3  Actionbase Now+          "지금 핫한 상품 top 10"
Lv.4  멀티홉                   "친구가 찜한 상품"  →  세션 2
```

**핵심**: 이 사다리는 처음부터 설계한 게 아니라 — **운영이 시스템을 자라게 한 흔적**이다.

### ⑤ 검증 4 레이어

신뢰는 한 가지 방법으로 만들지 않았다. 시스템 생애의 각 단계마다 다른 검증.

| 단계 | 방법 | 목적 |
|---|---|---|
| Dev | Tests as Contracts | 약속한 동작을 정의하고 지킨다 |
| Pre-Deploy | Shadow Testing → 세션 3 | 프로덕션 트래픽으로 검증 |
| Migration | Comparison Verification | Source ↔ Actionbase 일치 |
| Runtime | HBase Consistency | State·Index·Count 일관성 |

**핵심 한 줄 (발표 전체의 thesis)**:

> 문제가 안 생기는 시스템을 만든 게 아니라, 생겨도 알아채고 고칠 수 있는 시스템을 만들었습니다.

### ⑥ 핸드오프

두 가지 질문이 남는다:

1. "이 그래프로 무엇이 가능한가" → 세션 2 · 멀티홉
2. "프로덕션에서 정말 믿어도 되는가" → 세션 3 · 섀도

### ⑦ 닫기

> 오늘 이 길의 한 구간을 같이 걸어봤습니다.
> 다음 두 분이 그 다음 구간을 안내해 주실 겁니다.
> 감사합니다.

## 메타 메시지

핵심 한 줄이 발표 전체의 thesis 역할을 한다. 각 챕터는 사실 같은 메시지의 다른 표현:

| 챕터 | detect & correct의 형태 |
|---|---|
| 5단계 마이그레이션 | "롤백 경로를 항상 열어둔다" = 틀려도 되돌릴 수 있게 |
| 원장 vs 뷰 | 한 번에 안 갈아끼움 = 틀릴 수 있다는 전제 |
| 사다리 | "운영이 시스템을 자라게 했다" = 자라려면 안전하게 틀릴 수 있어야 함 |
| 검증 4 레이어 | 문자 그대로 detect & correct |
| "자라온 길" (제목) | 자란다는 건 = 매번 옳지 않았다는 것, 그래도 살아남았다는 것 |
